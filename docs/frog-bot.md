# Frog Bot 助理

OneFrog 的「AI 助理」由 [Frog Bot](https://github.com/llc370219/frog-bot) v0.1.2 驱动：一个聊天层负责和你对话，耗时的事交给后台 Agent。后台任务在服务器上继续运行，刷新或关掉页面都不会中断；任务卡可以暂停、恢复、取消和重试，需要你确认时会弹出审批卡片。

Frog Bot 不是第二套系统，它直接使用 OneFrog 已有的这些部分：

| 能力 | 使用的 OneFrog 部分 |
| --- | --- |
| 登录和账号 | OneFrog 登录。每个账号有自己的 Frog Bot、对话和工作区，互相看不到 |
| 模型 | 「设置 → 模型」里的默认主控：聊天用主控的模型路由，后台 Agent 用主控的协作路由 |
| 密钥 | 「密钥保险箱」。Frog Bot 的密钥卡片直接存进这里，没有单独的保险箱 |
| 定时 | 「模块 → 自动化」。在对话里让 Frog Bot 定时做事，会在自动化里新建一条，执行者是「Frog Bot（AI 助理）」；也可以直接在自动化页面选它 |
| 服务器 | 已登记且确认过 SSH 指纹的服务器。每条远程命令都要你单独批准一次，并写入 OneFrog 审计 |

## 权限

- Frog Bot 的文件工具只能访问当前账号自己的工作区，不能在面板所在的宿主机上执行 Shell。
- 需要操作服务器时，后台 Agent 先列出服务器，再对具体命令发起审批。批准只对卡片上的服务器和命令有效，远程命令不能「本任务内都批准」。
- 用到密钥时写成 `{{secret:NAME}}`，真实值只在执行那一刻替换，并且每次都要你确认。输出和日志里出现的密钥值（包括 base64、URL 编码等形式）会被替换成 `[secret:NAME]`。
- Frog Bot 只能引用由大写字母、数字和下划线组成的密钥名（例如 `GITHUB_TOKEN`）。保险箱里其他名字的密钥它看不到，原来的运维会话照常可用。
- 定时计划的新建、暂停、恢复和删除都要在审批卡片上确认，聊天里说「同意」不算数。计划到点执行时，命令和密钥仍然逐条审批；需要你处理时，自动化会显示「等待处理」，点「查看并处理任务」会打开 AI 助理。

## 与原有功能的关系

- 原来的群聊、Bot 专属会话、代码工作区和面板任务都在「运维会话」及原页面里，记录不会自动搬进 Frog Bot。
- 自动化里原有的计划不受影响，仍由原来选择的 Bot 执行。

## 数据

- 聊天事件、任务检查点和记忆按账号加密保存在 `OF_DATA_DIR/frog-bot/`，工作区文件也在这个目录下。面板的备份与迁移会一起打包。
- 密钥只保存在 OneFrog 的保险箱（数据库）里，Frog Bot 目录里没有密钥。

## 开发

- 前端通过 `/api/frog-bot/*` 访问，走 OneFrog 的登录和跨站请求校验，事件流支持断线续传。Frog Bot 随 OneFrog 一起构建和启动，不需要第二个服务。
- 代码基于 Frog Bot `0ca375c`（v0.1.2，MIT），位于 `internal/frogbot/` 和 `web/src/frogbot/`。宿主适配位于 `internal/api/frogbot.go`、`internal/api/frogbot_host.go` 和 `internal/bot/frogbot.go`。嵌入模式（`bot.Config.Host`）下，Frog Bot 自带的登录、模型设置、本地保险箱、定时器和多 Bot 侧栏都不启用。
