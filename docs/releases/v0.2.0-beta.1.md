# AI 助理改用 Frog Bot 完整架构，每个 Bot 都是一个助理

OneFrog v0.2.0-beta.1 测试版。AI 助理整体改用 Frog Bot 的架构，并和 OneFrog 的 Bot、服务器、审批、密钥保险箱和自动化打通。

## 变化

- AI 助理改用 Frog Bot 的完整架构：聊天层负责对话，要动手的事交给后台 Agent；后台任务有队列、检查点、暂停/恢复/取消/重试，卡住会被发现，面板重启后会接着跑，每个任务只汇报一次。
- 「Bot」页里每个启用的 Bot（「自定义模块」Bot 除外）都是 AI 助理里的一个助理，各自有对话、后台任务、私有记忆和工作区，同一账号下还有共享记忆。助理之间可以互相询问和留言。宽屏时左侧切换，窄屏时点顶部名字切换；「Bot」页恢复了「对话」按钮。
- 后台 Agent 直接使用 OneFrog 原有的服务器工具（执行命令、检查服务、接入服务器、安装探针、面板和模块操作、生成密钥），按 Bot 的职责提供，用的是这个 Bot 自己的模型路由，用量记在它名下。
- 对话页右上角可以给每个助理选「可直接操作的服务器」。选中的服务器按「设置 → 审批」的模式处理（智能模式下只有有风险的命令才问）；没选中的服务器每条命令都要确认。
- OneFrog 要求确认的操作，审批卡片只能「批准一次」，卡片上写明服务器、命令和原因。审批卡片和选项卡片仍是两种卡片。
- 自动化到点后进入执行者 Bot 的后台队列，自动化里指定的服务器在这次运行中算作选中的服务器，自动化自己的审批模式照常生效。「在 AI 助理中查看」会打开对应的助理。
- 移除单独的 `/frog-bot.html` 页面（会跳回面板），AI 助理直接在面板里渲染，浅色、深色和窄屏下的样式与面板一致。

## 接口

- 新增 `GET /api/frog-bot/bots`（助理列表，来自「Bot」页）和 `GET/POST /api/frog-bot/bots/{id}/scope`（可直接操作的服务器）。
- 每个助理的对话、任务、审批和事件流在 `/api/frog-bot/bots/{id}/*`。主控的 id 是 `main`，旧的 `frog-bot` 仍可用。
- `POST /api/frog-bot/bots` 不再新建助理，请在「Bot」页管理。

## 升级须知

- 升级会保留账号、设置、服务器、保险箱、Bot、自动化和 AI 助理的数据，容器会重启。没有数据库迁移，也不删除数据。
- 原来的 Frog Bot 成为主控的助理，对话、任务、记忆和工作区原样保留。其他 Bot 第一次打开时是空对话。
- 执行者是「Frog Bot（AI 助理）」的自动化改由主控执行，可以重新选执行者和服务器。
- 面板的备份与迁移会一起打包所有助理的数据和服务器选择。
- 主机指纹校验、灾难性命令拦截、密钥只在执行时替换并在输出中打码、不内置 Google 客户端密钥，这些都不变。

## 已知限制

- 面板首页的指令卡片、服务监控和订阅页的「让 Bot 检查」、「自定义模块」构建器，以及执行者是「自定义模块」Bot 或没有账号归属的自动化，仍由原来的任务引擎执行。
- 审批卡片 10 分钟内没处理会自动拒绝，无人值守的自动化也一样。
- 「Bot」页里的记忆只作为参考带进对话，助理自己记下的记忆单独保存，不会写回「Bot」页。
- 助理不能在 AI 助理页里新建或删除，请在「Bot」页管理；一个账号最多 32 个助理。

## 升级方式

在面板「设置 → 关于与更新」检查并升级；也可以在安装 OneFrog 的服务器上执行：

```bash
curl -fsSL https://raw.githubusercontent.com/llc370219/onefrog/main/install.sh | sudo OF_CHANNEL=beta bash
```

使用自定义安装目录的用户需继续指定原来的 `OF_INSTALL_DIR`。
