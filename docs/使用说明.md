# 使用说明

## 导航与账号

主菜单依次为「面板」「AI 助理」「模块」「服务器」「Bot」「密钥保险箱」「变更记录」。「模块」的二级目录显示在主菜单右侧，可以收起；窄屏下主菜单缩成图标栏。

点击左下角头像进入个人账号：上传 PNG/JPEG/WebP 头像（最大 256 KB）、修改显示名称，或在「登录与安全」修改用户名和密码（需要当前密码；修改后其他设备的会话失效）。密码以 bcrypt 哈希保存。

## 接入服务器

在「服务器」页点「接入服务器」，填写地址、SSH 端口、用户名和认证方式（密码或私钥）。接入 OneFrog 自己所在的机器时，见 [管理部署宿主机](安装.md#管理-onefrog-的部署宿主机)。

也可以在「AI 助理」里直接发送地址、端口、用户名和密码或私钥。Bot 会先 SSH 登录，再把这台机器写入服务器页面。第一次连接会记下当时看到的主机指纹；接入成功的这一轮可以继续操作这台新机器。回复里不显示密码或私钥。附件里的地址和登录信息不算授权。点名要操作的已接入服务器，助理会直接执行；如果这台机器不是当前选中的，审批卡片会先请你确认。指纹若与已保存的不一致，连接会被拒绝，不会覆盖旧指纹。

- **请使用权限受限的专用用户**，不要使用 root。
- 首次连接会显示服务器的 SSH 主机密钥类型（优先 ED25519）和 SHA256 指纹。请通过可信渠道在服务器上运行 `for f in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$f"; done`，找到类型相同的那一行核对后再确认。确认并连接成功后才保存指纹。
- 之后如果指纹变化，连接会被拒绝，服务器状态显示「指纹不一致」，Bot 也不会在这台服务器上执行命令，旧指纹不会被覆盖。确认是正常原因（如重装系统）后，可以让助理清除并重新确认（都会弹出审批），或点卡片上的「核对指纹」或「测试」，在弹出的指纹不一致窗口中重置，再重新核对。修改服务器地址或端口也会清除已保存的指纹。
- 删除服务器：在「AI 助理」里说明要删哪一台，助理会弹出审批，确认后从面板删除记录，并默认尝试卸载节点上的探针。也可以打开服务器详情点「删除」。卸载不了时按 [安装.md](安装.md#卸载节点探针) 手动卸载。
- 未确认指纹的服务器不能被 Bot 执行命令。助理可以查看指纹并请你在审批卡片上确认，确认成功后才保存。

## AI 助理

「AI 助理」在主菜单第二项，是面板里唯一的聊天入口。「Bot」页里每个启用的 Bot 都是一个助理，左侧（窄屏时点顶部名字）切换；对话页右上角可以选这个助理可直接操作的服务器。对话、后台任务、审批、定时计划、文件和权限见 [frog-bot.md](frog-bot.md)。服务器页的「交给 Bot」和密钥保险箱的「发给助理」会打开主控，并把内容放进输入框；「Bot」页的「对话」按钮打开对应的助理。

v0.1.33 移除了原来的「运维会话」（Bot 单聊、隔离项目、收件箱对话列表）和「代码工作区」。旧对话仍在数据库里，没有删除，只是页面上不再显示。

### 面板首页

- 面板首页可以直接操作，不必先打开对话。模型接上后，点「检查面板」「处理告警」「检查更新」，或写一句话再点「执行」。主控会改模块开关、启停 Bot、测试已接入服务器的 SSH、删除服务器记录，并检查版本。服务监控和订阅页的「让 Bot 检查」也交给主控，结果显示在面板卡片上。
- 没接上渠道和模型时，首页提示「去接模型」。连不上模型时，结果里会写明是接口连不上，还是渠道没有密钥或登录。
- 升级、删除服务器、确认或清除 SSH 主机指纹、把保险箱里的密钥写入渠道、更改审批模式、修改 Bot 工作指令，都会先弹出审批。助理读不到保险箱明文，只能按名称调用。指纹和已保存的不一致时不会覆盖；更换要先审批清除，再审批确认新指纹。
- 审批方式在首次登录时由你选择，也可在设置中修改。「智能审批」下只读命令直接执行，有风险的命令会显示目标服务器、命令和规则证据，由你批准或拒绝；没回应前命令不会执行。「替我审批」由独立审批模型给出放行、拒绝或需要你确认三种结论，模型不可用或结果无效时转为你确认。「关闭审批」下命令直接执行。其他模式见 [设置与模型配置.md](设置与模型配置.md#命令审批)。
- 单轮工具调用有上限，在设置的「单 Bot 最大循环轮数」里调整（1–24）。后台任务里用完一轮不算失败：运行时自动开下一轮接着做，任务总预算约为单轮上限的 4 倍，已经完成的步骤不会重做。只有总预算或任务生命周期（当前 12 小时）用完时才会停下，并写下做到哪、关键发现和下一步。
- 主控需要你拍板时会在卡片里放选项（2–6 个）。每张卡片只能回答一次，由服务端保证；选项卡片不用于确认命令，命令仍走审批。

## Bot 管理

「Bot」页列出每个 Bot 的名称、职责、当前模型、启用状态和 Token 用量。可以创建、重命名、修改职责与工作指令、删除、绑定独立的渠道和模型或恢复跟随默认。停用的 Bot 不能发起对话或接受派工。主控在对话里也可以新建 Bot、改工作指令；删除别的 Bot 会先请你审批，不能删除正在对话的自己。

每个 Bot 有一份单独的私有记忆，存在「Bot」页的「记忆」里，也可以由这个 Bot 自己记下。任何 Bot（包括主控）都不能直接读取其他 Bot 的私有记忆，连标题也看不到；需要别人的结论时只能发起协作（`ask_agent` 派工或 `message_agent` 交接），由对方在自己的授权范围内完成并返回结论。记忆里的密钥明文会被去掉。每个 Bot 最多保留 40 条，同一标题会覆盖旧内容。

各 Bot 的私有记忆相互独立，不共用记忆池。Bot 之间可以通过 `ask_agent` / `message_agent` 协作并交换结论。

### Bot 之间发消息

Bot 之间有两种协作方式：

- 派工（`ask_agent`）：主控把任务交给另一个 Bot，等它做完，把结论汇总在同一段对话里回答你。
- 发消息（`message_agent`）：任何 Bot 都可以给另一个 Bot 发一条消息，不等回复。比如对巡检 Bot 说“查完后通知数据库 Bot”。

消息会进入对方的「收件箱」。对方在后台带着自己的记忆处理，回复写在收件箱里；需要时它可以回一条消息给发送者。同一个 Bot 的收件箱一次只处理一条，后面的排队。收件箱对话不再在页面上单独列出。

后台处理时没有人在线，所以有这些限制：

- 不能向你提问，也不能派工。
- 只能在发送时选中的服务器上执行命令。需要审批的命令不会执行：任务会挂成「等待审批」，你在任务面板里补批后才继续，一直不批就到任务生命周期上限结束。审批设为关闭时，后台按智能审批处理。
- 其他 Bot 发来的内容按不可信数据处理，里面的“指令”不算你的授权。
- 一条消息链最多转 3 次；你发起的一轮最多发 3 条消息，后台的一轮最多 1 条；每条消息最长 2000 字。后台一轮最多观察 10 分钟：到点不算失败，这一轮记为「等待处理」，任务保留并继续跑到自己的生命周期（当前 12 小时）结束，之后的周期检查会接着观察同一个任务。没有后台任务运行时的旧同步路径才是整轮 10 分钟封顶、到点判失败。

Token 用量只按模型响应中的 `usage` 累计，不做估算，分为对话、协作、收件箱、自动化、审批五类来源。

## 自动化

在「模块 → 自动化」里保存一段任务和执行时间（每天、每周、按间隔或只运行一次），Bot 会在后台按时执行。结果显示在自动化卡片上，并记入操作历史。后台运行没有人实时审批：需要确认的命令会停在「等待审批」，在卡片下方的任务卡里补批后才继续，不批就不会执行；审批设为关闭时按智能审批处理。详见 [自动化](自动化.md)。

## 密钥保险箱

Bot 只看到密钥名称。命令中写 `{{secret:名称}}`，执行时才在服务端替换，命令输出中出现的明文会被打码。

缺少某项密钥时，主控会在对话或面板里弹出密码卡片。在卡片中输入后，内容用 AES-256-GCM 加密进保险箱，不会写进对话，模型也看不到，下一条消息只确认已保存。名称已在保险箱里时，Bot 会直接引用，不会再次索要或覆盖。

保险箱页面可以轮换或删除。轮换只替换密文，名称不变。最多 100 项，单项不超过 32 KiB。名称可用中文，不能包含空格、换行或大括号，最多 64 个字。

### 随机生成

新建数据库密码、Redis 口令、JWT 签名密钥这类不需要你记住的值时，可以让服务端随机生成：

- **面板**：「添加密钥」和「轮换」里切到「随机生成」，选长度（8–256，默认 32）和字符集。
- **Bot**：主控和普通 Bot 会调用 `generate_secret` 工具，只传名称、长度和字符集。工具结果里只有名称和 `{{secret:名称}}` 引用，Bot 随后在命令里引用它。
- **接口**：`POST /api/secrets/generate`（`{name, description, length, charset}`）新建；`POST /api/secrets/:id/generate`（`{description, length, charset}`）轮换。返回值只有元数据。

字符集可选 `alnum`（大小写字母和数字）、`symbols`（再加安全符号）、`hex`、`base64url`、`digits`。值用系统安全随机数（`crypto/rand`）生成后立即用 AES-256-GCM 加密，浏览器、对话记录和模型都拿不到明文；命令输出里出现时同样会被打码。Bot 不会覆盖已有的同名密钥，`model-key` 是保留名称。

## 服务器探针

一台服务器一张卡片，宽屏一行三张。卡片上依次是：

- **标题**：国旗（根据资产的地区或服务器名推断，例如 `TYO-xxx`、`洛杉矶`）、名称、在线状态和已运行时间。
- **配置**：地区、核数、内存、磁盘、系统，旁边的标签是资产里登记的套餐（没有时显示架构）。
- **资源**：CPU、内存、根分区磁盘和负载，用分段条显示。超过 75% 变黄，超过 90% 变红。负载按核数折算，鼠标悬停可看 1 / 5 / 15 分钟。
- **网络**：左边是实时上传 / 下载速率，右边是本月出站 / 入站流量。流量由面板按自然月累计，节点重启后也会接着累加，上个月的总量会保留。
- **流量**：设了月流量额度时，显示「已用 / 额度」和进度条，左边是计费方式（双向、只算出站、只算入站、取较大者），点它可以修改。没设额度时，右上角显示「Out / In / Total」，方块按出站（蓝）和入站（绿）的比例着色；点「设置额度」直接填额度和计费方式。服务器还没登记资产时，会先打开资产登记。
- **三网延迟**：所选省份电信、联通、移动的当前延迟和丢包，下面的色块是最近 18 次检测的记录。绿色正常，黄色偏高（100ms 以上或少量丢包），橙色较高，红色很差或超时。
- **底栏**：剩余天数和续费金额（来自「资产与订阅」）、运行中的服务（来自「服务监控」最近一次检测）。

详情页还有 Swap、TCP 表项、进程数、上月流量和最近的趋势图。设计参考了 [Komari](https://github.com/komari-monitor/komari) 的轻量探针思路，代码为独立实现。

### 三网延迟

第一次给服务器配置探针时，面板（以及让助手安装时）会先问「三网延迟测哪个省份」。按你的用户或你自己常在的地区选；不需要可以选「不测三网」。探针用 TCP 握手测 `<省份>-<ct|cu|cm>-v4.ip.zstaticcdn.com` 的 80 端口，因为不少运营商节点不回 ICMP。支持 31 个省级地区。三网之外还可以再加几个自定义目标（用 ICMP Ping），合计最多 8 个。

**已经装过探针的服务器**要换成三网检测：在卡片上点「选择省份」或「接入探针」重新生成凭据并重装探针，或者直接让助手「给 xxx 重装探针，三网测广东」。旧版探针不支持 TCP 检测。

接入：

1. 在服务器卡片点「接入探针」。
2. 填写被监控节点能访问的主控地址，**请使用 HTTPS 地址**（上报凭据随每次请求发送）；不要给远程节点填 `127.0.0.1`。
3. 选择三网延迟测试的省份，按需填写其他检测目标、采集间隔和网卡，生成该节点专属的上报凭据并下载配置和脚本（凭据只出现在下载的配置里）。
4. 在节点上准备 Python 3.8+（ICMP 检测需要 `ping`），把两个文件放在同一目录，执行 `chmod 600 onefrog-probe.json && python3 onefrog-probe.py ./onefrog-probe.json`。长期运行请自行配置 systemd 等服务管理器。

通过「接入服务器」向导自动部署时，探针以 systemd 服务 `onefrog-probe` 运行，文件在 `/opt/onefrog-probe`，配置在 `/etc/onefrog-probe/probe.json`（v0.1.1 及更早在 `/opt/onefrog/probe`，重新接入时自动迁移）。卸载见 [安装.md](安装.md#卸载节点探针)。没有初始化步骤的模块在接入时记为「跳过」，不影响接入结果。

已经接入的服务器，主控助手可以直接调用 install_probe 安装或重装只读探针，不必再去下载面板自己的网页或前端脚本。新的 SSH 主机指纹会出现在审批卡片上，你批准后才继续，助手不能自己确认。

脚本只读取 `/proc` 和文件系统容量、按配置执行 TCP / ICMP 延迟检测并上报，不接收任何远程指令。超过 90 秒未上报显示离线。服务端只保存凭据的 SHA-256，保留每个节点最近 120 个采样（默认 15 秒一次，约 30 分钟），不是长期时序数据库；按月累计的流量单独保存。

## 服务监控（官方模块）

从「模块 → 服务监控」、首页服务卡片或服务器详情的「运行服务」进入。点击「检测」或「检测全部服务器」，通过已保存并确认指纹的 SSH 连接，查看：

- systemd 已加载服务的运行、停止和失败状态。
- Docker 容器的名称、状态、镜像与端口映射，包括已经停止的容器。
- TCP / UDP 监听地址、端口与当前用户可见的进程名称。

默认筛选运行中 / 监听中的项目，可切换全部状态、异常状态，或搜索服务名、镜像和端口。服务详情可直接交给 AI 检查；对话中也可要求「检查这台服务器有哪些服务在运行」，AI 调用 `inspect_services` 后会同步更新模块快照。后续修改仍使用现有命令审批。

检测需要节点提供 Python 3；systemd、Docker、`ss` 分别按实际是否安装与当前用户权限显示，不会自动安装软件、启动或停止服务。非 root 用户可能看不到其他用户的进程名。未检测显示「尚未检测」，来源不可用会提示原因；失败时保留上次成功数据并明确标记。每类最多返回 500 项，截断会有提示。

页面每 15 秒同步服务端快照，获取实时状态需再次点击检测或让 AI 检测。快照保存在当前服务进程内存中，重启面板后需重新检测；不读取环境变量、启动参数、日志或配置文件，凭据仅由服务端调用。

### 自选监控项与轮询

检测出服务列表后，勾选表格第一列即可把 systemd 服务、Docker 容器或监听端口加入监控（端口按监听地址匹配，例如 `0.0.0.0:80`），点「保存监控」生效，「撤销」放弃未保存的改动。筛选栏的「已监控」只显示勾选的项目。

保存后面板在后台按设定间隔轮询有监控项的服务器（30–3600 秒，默认 60 秒），保存时立即检测一次。每台服务器最多监控 100 项。监控表显示每一项的状态：

面板首页的服务监控卡片只列出已保存的监控项，不列出全部服务器。同一行从左到右是状态、监控项、所在服务器、类型，异常项排在前面。这张卡片独占一行，放在「需要处理」「自动化」「订阅」那一排的下面；原来的位置改成自动化卡片。

| 状态 | 含义 |
| --- | --- |
| 待检测 `pending` | 刚加入，还没轮询到 |
| 正常 `ok` | 服务运行中、容器运行中或端口在监听 |
| 异常 `fault` | 找到了，但处于停止、失败、退出状态，或容器健康检查不通过 |
| 缺失 `missing` | 本次检测结果里找不到该项 |
| 无法判断 `unknown` | SSH 失败、采集来源不可用，或列表被截断无法确认 |

某项第一次变为异常或缺失时，「历史记录」里写一条失败记录；恢复正常时写一条成功记录。中间出现「无法判断」不会重复报警。监控配置和最近状态加密保存在 `servicewatch.enc`，重启面板后继续轮询。

## 资产与订阅

在「模块 → 资产与订阅」记录 VPS、域名等的提供商、套餐、计费周期、金额、付款日、到期日、自动续费等信息（账号栏只保存备注，不保存密码）。

- 剩余价值 = 本期金额 × 剩余天数 ÷ 周期总天数；已到期或停用为 0；14 天内到期标为即将到期。
- 折合月费：年付 ÷ 12、季付 ÷ 3，一次性费用不计入。
- 「模块管理」Bot 可以通过对话查看和开关面板模块，登记、修改、删除资产记录，以及维护自定义模块的数据；它不能执行服务器命令。

数据加密保存在 `assets.enc`。

## 自定义模块

在「模块 → 自定义模块」的构建器里，用自然语言或 HTML/CSS/JS 源码构建自定义交互模块（例如点击打卡记述卡片、运维待办清单、专注计时器、常用入口面板）：

- 新建模块会立即出现在「模块 → 自定义模块」目录，并默认展示在面板首页；修改已有模块界面或删除模块会先弹出审批确认，更新代码时保留已保存的状态与记录。
- 每个自定义模块运行在无网络、独立不透明源（`sandbox allow-scripts`）的隔离沙箱内，不能读取 Cookie 或保险箱明文，仅能通过内置 `window.onefrog` 接口读写该模块自身的数据。
- 模块源码与状态记录加密保存在 `devmodules.enc`。

## 主要接口

- `GET /api/services`：查询现有服务器的服务检测快照，不触发 SSH。
- `POST /api/servers/:id/services/scan`：只读检测单台服务器并更新共享快照。均需登录，POST 还需 CSRF 请求头。
- `GET /api/services/watch`、`PUT /api/services/watch`：读取 / 保存服务监控配置，返回 `{interval_seconds, servers, status}`。PUT 体为 `{"interval_seconds":60,"servers":{"<服务器ID>":[{"kind":"systemd|docker|ports","name":"…"}]}}`，保存后立即触发一次轮询。

所有接口都需要登录；写请求需带 `Content-Type: application/json`（上传附件为 multipart）和请求头 `X-OneFrog-CSRF: 1`。

| 接口 | 说明 |
| --- | --- |
| `GET /api/auth/me`、`PUT /api/auth/profile` | 当前账号 / 修改资料与登录信息 |
| `GET /api/sessions/:id/messages` | 读取一条会话的消息（面板任务卡和自定义模块构建器使用） |
| `POST /api/tasks`、`GET /api/tasks`、`GET /api/tasks/:id` | 提交 / 列出 / 读取持久任务。提交返回 202 + 任务视图（`{"items":[…]}` 是列表，单条是任务视图）；带 `client_request_id` 重试是幂等的，同一编号换了目标、会话、附件或选项会返回 409 |
| `POST /api/tasks/:id/pause\|resume\|cancel`、`POST /api/tasks/:id/guidance` | 暂停 / 恢复 / 取消任务，或追加引导 |
| `POST /api/tasks/:id/approvals/:approvalID` | 审批任务的挂起命令，体为 `{"allow":true,"reason":"…"}`。必须同时给出任务 id 和审批 id，决策持久化在任务上，重新连接后仍可作出；任务面板的「批准 / 拒绝」走的就是这个接口 |
| `GET/PUT /api/settings/approval` | 读取 / 修改命令审批模式 |
| `GET /api/update`、`POST /api/update/check`、`PUT /api/settings/update` | 更新状态（`current`、`latest`、`url`、`notes`、`available` 等，仅读缓存）/ 立即检查（30 秒内重复返回 429）/ 开关自动检查 `{"enabled":true}` |
| `GET /api/bots`、`POST /api/bots`、`PUT /api/bots/:id`、`PUT /api/bots/:id/enabled`、`DELETE /api/bots/:id` | Bot 列表 / 创建 / 修改 / 启停 / 删除 |
| `GET /api/usage` | Token 用量 |
| `POST /api/attachments`、`GET /api/attachments/:id/content` | 上传 / 读取本人附件 |
| `POST /api/servers/:id/test` | SSH 测试；可带 `{"fingerprint":"SHA256:…"}` 确认首次指纹 |
| `POST /api/servers/:id/host-key/reset` | 清除已保存的主机指纹 |
| `GET /api/monitor`、`POST /api/servers/:id/probe/token` | 探针状态 / 生成上报凭据 |
| `POST /api/probe/report` | 节点上报（Bearer 节点凭据，不能访问其他接口） |
| `GET/POST /api/assets`、`PUT/DELETE /api/assets/:id` | 资产与订阅 |
| `GET/POST /api/dev/modules`、`GET/PUT/DELETE /api/dev/modules/:id`、`POST /api/dev/modules/:id/data` | 自定义模块与沙箱数据 |


持久任务的审批挂在任务上，不会因为关掉页面或连接超时而自动放行或作废：它一直等你决定，直到任务自己的生命周期（当前 12 小时）用完。
