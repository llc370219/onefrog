# 安装与部署

## 一行命令安装

在一台 Linux 服务器（x86_64 或 arm64，建议 ≥512 MB 内存、1 GB 可用磁盘）上以 root 执行：

```bash
curl -fsSL https://raw.githubusercontent.com/llc370219/onefrog/main/install.sh | sudo bash
```

安装脚本需要 `curl`（下载 Docker 安装脚本和做健康检查都要用到）。精简系统上没有 `curl` 时，可以用 `wget` 运行安装脚本，脚本会先用 apt / dnf / yum 自动安装 `curl`（失败时会提示手动安装）：

```bash
wget -qO- https://raw.githubusercontent.com/llc370219/onefrog/main/install.sh | sudo bash
```

### 支持的系统

| 系统 | 版本 |
| --- | --- |
| Debian | 12、13 |
| Ubuntu | 22.04、24.04 及更新版本 |
| Rocky Linux / AlmaLinux / CentOS Stream / RHEL | 9、10 |
| Fedora | 当前维护中的版本 |

其他能运行 Docker Engine 和 compose 插件的发行版一般也可以用，但没有测试。Debian 11 及更早、Ubuntu 21.10 及更早、CentOS 7/8 等已经停止维护（EOL）的系统，软件源往往已经下线，Docker 很可能装不上：没有 Docker 时脚本会直接退出并说明原因。已经自己装好 Docker 的话会继续安装；确实要在这类系统上尝试自动安装 Docker，带上 `OF_ALLOW_UNSUPPORTED_OS=1`。Docker 安装失败（例如 `apt-get update` 报错）时，脚本会停下并提示先修复软件源或[手动安装 Docker](https://docs.docker.com/engine/install/)。

想先阅读脚本再运行：

```bash
curl -fsSLO https://raw.githubusercontent.com/llc370219/onefrog/main/install.sh
less install.sh
sudo bash install.sh
```

### 脚本做了什么

1. 确认系统是 Linux、当前是 root、有 `curl`（没有就自动安装），并检查系统版本是否已停止维护（见上表）。
2. 没有 Docker 时先打印提示，10 秒后用官方脚本 `https://get.docker.com` 安装（Ctrl+C 取消；`OF_INSTALL_DOCKER=0` 则直接退出）。
3. 确定 compose 项目名（见下文「[多个实例](#在同一台机器上安装多个实例)」），检查它没有被别的安装目录占用、端口没有被其他程序占用。
4. 没有 `/opt/onefrog/.install.env` 时生成一份（权限 600，含随机 20 位初始密码）；已有就沿用，不改账号。
5. 未指定 `OF_PUBLIC_URL` 时，向外部服务 `https://ifconfig.me` 查询本机公网 IPv4，只用于打印访问链接；查询失败则用网卡地址。不希望发出这个请求时，直接指定 `OF_PUBLIC_URL`。
6. 写入 `/opt/onefrog/docker-compose.yml`，拉取预构建镜像 `ghcr.io/llc370219/onefrog`（目标机器不需要 Go/Node）。
7. 启动容器，检查 `/api/health`，打印链接、用户名、初始密码。面板以明文 HTTP 对外开放时会额外打印警告。

### 安装选项

环境变量写在 `sudo` 和 `bash` 之间：

```bash
curl -fsSL https://raw.githubusercontent.com/llc370219/onefrog/main/install.sh \
  | sudo OF_BIND_ADDR=127.0.0.1 OF_PUBLIC_URL=https://ops.example.com bash
```

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `OF_VERSION` | `latest` | 镜像版本，例如 `v0.1.1` |
| `OF_PUBLISH_PORT` | `8080` | 宿主机端口（容器内固定 8080） |
| `OF_BIND_ADDR` | `0.0.0.0` | 绑定地址。放在 HTTPS 反向代理后面时**务必**用 `127.0.0.1` |
| `OF_PUBLIC_URL` | `http://公网IP:端口` | 打印的链接；以 `https://` 开头时登录 Cookie 带 Secure |
| `OF_ADMIN_USER` | `admin` | 初始用户名（首次登录必须修改） |
| `OF_APPROVAL_MODE` | 不设置 | 预设命令审批模式（`off` / `smart` / `manual` / `plan`），用于无界面安装；只在尚未选择时生效。不设置时首次登录会让你选择 |
| `OF_UPDATE_CHECK` | `1` | `0`：面板不再向 GitHub 查询新版本（见下文「升级」） |
| `OF_INSTALL_DIR` | `/opt/onefrog` | 安装目录（绝对路径）。升级时要带上同一个值 |
| `OF_PROJECT` | 见说明 | docker compose 项目名。`/opt/onefrog` 默认是 `onefrog`，其他安装目录默认是 `onefrog-<目录名>`；首次安装后保存在 `.install.env`，之后不能更改 |
| `OF_ALLOW_UNSUPPORTED_OS` | `0` | `1`：在已停止维护的系统上也尝试自动安装 Docker |
| `OF_INSTALL_DOCKER` | `1` | `0`：没有 Docker 时直接退出 |
| `OF_BUILD_FROM_SOURCE` | `0` | `1`：克隆 `OF_REPO` 并在本机构建镜像（需要 git、约 2 GB 内存） |
| `OF_REPO` / `OF_IMAGE` | 本仓库 / `ghcr.io/llc370219/onefrog` | 源码地址 / 镜像名 |

服务端还支持以下运行时变量（写入 `/opt/onefrog/.install.env` 后执行 `cd /opt/onefrog && sudo docker compose -p onefrog up -d`）：

| 变量 | 说明 |
| --- | --- |
| `OF_TRUSTED_PROXIES` | 信任哪些反向代理传来的 `X-Forwarded-For`（逗号分隔的 IP/CIDR）。默认信任本机和内网地址；设为 `none` 则不信任任何代理。影响登录限流按哪个 IP 计数。 |
| `OF_MASTER_KEY` | 加密主密钥。默认在数据目录生成 `master.key`。 |
| `OF_UPDATE_REPO` | 检查更新所用的 GitHub 仓库（`owner/name`），默认 `llc370219/onefrog`；维护分支时改成你自己的仓库。 |
| `OF_GOOGLE_OAUTH_CLIENT_ID` / `OF_GOOGLE_OAUTH_CLIENT_SECRET` | 启用 Google Antigravity 登录，见 [设置与模型配置.md](设置与模型配置.md#google-antigravity-登录需自行配置)。 |

### 在同一台机器上安装多个实例

每个安装目录对应一个独立的 compose 项目和数据卷（`<项目名>_onefrog-data`）。默认目录 `/opt/onefrog` 的项目名固定为 `onefrog`（数据卷 `onefrog_onefrog-data`，与旧版本相同）；其他目录默认用 `onefrog-<目录名>`。第二个实例需要不同的安装目录和端口：

```bash
curl -fsSL https://raw.githubusercontent.com/llc370219/onefrog/main/install.sh \
  | sudo OF_INSTALL_DIR=/opt/onefrog-2 OF_PUBLISH_PORT=8081 bash
```

- 以后升级第二个实例时也要带上 `OF_INSTALL_DIR=/opt/onefrog-2`；不带就会升级默认目录里的实例。
- 端口已被其他程序或容器占用时，脚本会停下并提示换一个 `OF_PUBLISH_PORT`。
- 项目名已经被另一个安装目录的容器使用时，脚本会拒绝继续，不会接管那边的容器。
- v0.1.1 及更早的版本不区分安装目录，第二个实例会接管第一个实例的容器和数据卷。如果你这样装过，两个目录实际共用 `onefrog` 项目和同一份数据；升级时只升级最后安装的那个目录，另一个目录可以删除，或者在新目录里用新的项目名重新安装。

重复执行安装命令即升级：沿用已有 `.install.env`，**不会重置账号**；传入新的 `OF_PUBLISH_PORT` / `OF_BIND_ADDR` / `OF_PUBLIC_URL` / `OF_APPROVAL_MODE` / `OF_UPDATE_CHECK` 会写回配置。详见下文「[升级](#升级)」。

## 升级

### 检查更新

面板服务端在启动约 15 秒后和之后每 12 小时，向 GitHub 查询一次 `https://api.github.com/repos/llc370219/onefrog/releases/latest`（10 秒超时，结果缓存在内存中）。这只是一个匿名的只读请求，不发送你的任何数据，也**不会自动下载或安装**。

- 发现比当前版本更高的正式版时，面板顶部显示提示条，可查看更新说明并复制升级命令；点 × 后同一版本不再提示。
- 「设置 → 关于与更新」显示当前版本、最新版本和上次检查时间，可以立即检查，或关闭自动检查（立即生效）。
- 想彻底禁止访问 GitHub：安装时带 `OF_UPDATE_CHECK=0`，或把它写入 `.install.env` 后重新运行安装命令。此时设置里的开关不可用。
- 自行构建、没有版本号的开发版本（显示为 `dev`）不检查更新。

### 升级步骤

在安装 OneFrog 的服务器上以 root 执行任一方式（安装时改过 `OF_INSTALL_DIR` 的，请带上同一个值，并把下面的 `/opt/onefrog`、`onefrog` 换成你的安装目录和项目名；项目名记录在安装目录的 `.install.env` 里，面板的升级提示也会显示正确的命令）：

```bash
# 方式一（推荐）：重新运行安装命令，同时会更新 docker-compose.yml
curl -fsSL https://raw.githubusercontent.com/llc370219/onefrog/main/install.sh | sudo bash

# 方式二：只拉取最新镜像并重建容器
cd /opt/onefrog && sudo docker compose -p onefrog pull && sudo docker compose -p onefrog up -d
```

- 两种方式都会保留 `.install.env`（账号、端口、绑定地址等）和数据卷（账号、设置、服务器、密钥保险箱、对话、登录会话、变更记录、`master.key`，见「数据与备份」）。升级不会再显示初始密码，请用你自己设置的账号登录。
- 版本没有变化时，安装脚本会提示「已是最新版本」。
- 容器会重启，正在生成的回复会中断；登录状态和对话记录都会保留。
- **从 v0.1.0 升级**：v0.1.0 的面板没有更新提示。请在服务器上重新运行一次安装命令（安装时改过 `OF_INSTALL_DIR` 的，带上同一个值），账号和数据都会保留。
- 固定到某个版本：`curl -fsSL …/install.sh | sudo OF_VERSION=v0.1.1 bash`。回退同理，指定旧版本号即可。
- 升级前建议先按「数据与备份」备份数据卷。
- 面板没有一键升级按钮：容器不挂载 Docker socket，不能也不应该自己替换自己。

### 第一次登录

用打印的用户名和初始密码登录后必须设置新账号：用户名不能仍为 `admin`（3–64 位字母、数字、`_`、`.`、`-`），新密码 8–72 字节且不同于初始密码。改完之前其他接口都返回 403。连续输错密码会被临时锁定（同一用户名 15 分钟内 5 次、同一 IP 20 次，锁定时间从 1 分钟逐步增加到 30 分钟）。

## HTTPS 反向代理（强烈推荐）

面板保存服务器的 SSH 凭据并能执行远程命令，不要长期通过明文 `http://IP:8080` 登录。

```bash
curl -fsSL https://raw.githubusercontent.com/llc370219/onefrog/main/install.sh \
  | sudo OF_BIND_ADDR=127.0.0.1 OF_PUBLIC_URL=https://ops.example.com bash
```

Caddy（自动申请证书）：

```caddyfile
ops.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Nginx 需要同时转发 WebSocket，并保留 `Host`（实时对话会校验来源）：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 1h;
}
```

**Docker 会绕过主机防火墙**：发布的端口通过 Docker 自己的 iptables/nftables 规则放行，ufw、firewalld 的拒绝规则可能不起作用。只想经反向代理访问时，必须绑定 `127.0.0.1`。

## 安全建议

- **使用权限受限的 SSH 用户。** 不要把 root 交给 OneFrog；为它创建专用用户，只授予需要的权限（例如只读查看日志、指定的 `sudo` 命令）。AI 生成的命令可能出错或被日志、网页等内容误导。
- **建议开启「智能审批」。** 首次登录会让你在「智能审批」和「关闭审批」之间选择。智能审批能减少但不能消除风险，规则可能漏判；详见 [设置与模型配置.md](设置与模型配置.md#命令审批)。
- **核对 SSH 主机指纹。** 首次连接时面板显示服务器的密钥类型（ED25519 / ECDSA / RSA）和 SHA256 指纹，确认后才保存；之后指纹变化会拒绝连接，不会自动覆盖，服务器状态显示为「指纹不一致」。核对方法：通过云厂商控制台等可信渠道登录服务器，执行

  ```bash
  for f in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$f"; done
  ```

  在输出中找到末尾类型与面板显示一致的那一行（例如 `(ED25519)`），比较 SHA256 值。面板优先使用 ED25519 密钥；v0.1.1 及更早保存的指纹没有记录类型（通常是 ECDSA），继续有效。确认是重装系统等正常原因后，在服务器卡片上点「核对指纹」或「测试」，在指纹不一致的弹窗里勾选确认并「重置已保存的指纹」，再重新核对新指纹。
- **探针上报使用 HTTPS 地址。** 探针凭据随每次上报发送，使用 `http://` 主控地址会以明文传输。
- **保护数据目录。** `master.key` 与加密数据保存在同一个数据卷中：拿到整个数据卷（或备份）的人可以解密全部内容。需要分开保存时，用 `OF_MASTER_KEY` 从外部提供主密钥，并单独备份。
- 容器内服务以非 root 用户（uid 10001）运行。
- 发现安全问题请通过 GitHub 私下报告（Security → Report a vulnerability），不要公开提 issue。

## 数据与备份

一行命令安装使用内置的 `memory` 驱动（不需要数据库），数据在 Docker 卷 `onefrog_onefrog-data`（容器内 `/app/data`）。

所有数据在重启和升级后都会**保留**，除账号文件外均用 `master.key` 以 AES-GCM 加密，每次写入先写临时文件再原子替换：

| 文件 | 内容 |
| --- | --- |
| `accounts.json` | 账号与密码哈希（bcrypt） |
| `servers.enc` | 服务器与 SSH 凭据 |
| `secrets.enc` | 密钥保险箱 |
| `sessions.enc` | 登录会话（过期、退出登录或修改密码后删除） |
| `chats/*.enc` | 对话与消息，每个对话一个文件 |
| `history.enc` | 变更记录 |
| `modules.enc` | 自定义模块改动 |
| `bots.enc`、`settings.enc`、`oauth.enc`、`usage.enc`、`assets.enc` | Bot、设置、OAuth 登录与风险确认、Token 用量、资产与订阅 |
| `monitor.json`、`onboarding.json` | 探针数据、接入向导 |
| `uploads/` | 附件 |
| `master.key` | 主密钥 |

保留上限：最近 500 个对话、每个对话最近 2000 条消息、最近 2000 条变更记录、1000 个登录会话，超出时删除最旧的。

v0.1.1 及更早的版本只在内存中保存对话、变更记录、密钥保险箱、登录会话和模块改动；升级后这些内容从空开始，之后会正常保存。另有实验性的 PostgreSQL 驱动（`OF_DRIVER=postgres` + `DATABASE_URL`），尚未经过完整的生产验证。

备份：

```bash
sudo docker run --rm -v onefrog_onefrog-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/onefrog-data-$(date +%F).tgz -C /data .
```

备份包含 `master.key` 和加密的 SSH 凭据，请妥善保管。

## 常用命令与卸载

以默认安装目录 `/opt/onefrog`（项目名 `onefrog`）为例；其他目录请换成 `.install.env` 里的 `OF_PROJECT`：

```bash
cd /opt/onefrog
sudo docker compose -p onefrog ps
sudo docker compose -p onefrog logs -f
sudo docker compose -p onefrog restart
```

卸载面板：

```bash
cd /opt/onefrog
sudo docker compose -p onefrog down          # 停止并删除容器，保留数据卷
sudo docker volume rm onefrog_onefrog-data   # 删除所有数据（不可恢复）
sudo docker image rm $(sudo docker image ls -q ghcr.io/llc370219/onefrog)   # 删除镜像
cd / && sudo rm -rf /opt/onefrog             # 删除安装目录和初始密码文件
```

### 卸载节点探针

在面板里删除服务器时（服务器详情 →「删除」），默认勾选「同时卸载节点上的探针」：面板会用已确认的主机指纹通过 SSH 连接，停止并删除探针服务和文件，并显示结果。连不上、指纹不一致、或 SSH 用户没有 root / 免密 sudo 时会跳过，服务器照常删除，需要在节点上手动卸载：

```bash
sudo systemctl disable --now onefrog-probe.service
sudo rm -f /etc/systemd/system/onefrog-probe.service
sudo systemctl daemon-reload
sudo rm -rf /opt/onefrog-probe /etc/onefrog-probe
# v0.1.1 及更早的版本把探针放在下面两个位置
sudo rm -rf /opt/onefrog/probe /etc/onefrog/probe.json
```

从 v0.1.2 起探针安装在 `/opt/onefrog-probe`，配置在 `/etc/onefrog-probe/`，和面板的安装目录分开：在同一台机器上卸载面板（`rm -rf /opt/onefrog`）不会再删掉探针。旧版本装在 `/opt/onefrog/probe` 的探针会在重新接入时自动迁移。手动用下载的脚本运行的探针，停掉对应进程并删除那两个文件即可。

## 排错

- **端口被占用**：带上 `OF_PUBLISH_PORT=8081` 等未占用的端口重新运行安装命令。
- **提示项目名已被另一个安装目录使用**：见「[在同一台机器上安装多个实例](#在同一台机器上安装多个实例)」。
- **系统已停止维护 / Docker 安装失败**：见「[支持的系统](#支持的系统)」。
- **服务器显示「指纹不一致」**：见「安全建议」中的核对 SSH 主机指纹。
- **拉取镜像失败**：确认能访问 `ghcr.io`，或指定 `OF_VERSION`；也可用 `OF_BUILD_FROM_SOURCE=1` 在本机构建。
- **健康检查失败**：`cd /opt/onefrog && sudo docker compose -p onefrog logs`（项目名见 `.install.env` 的 `OF_PROJECT`）。
- **打印的链接不对**：带上正确的 `OF_PUBLIC_URL` 再运行一次安装命令，账号不会被重置。
- **实时对话连不上 / 提示来源不匹配**：反向代理要转发 WebSocket 并保留 `Host`；`OF_PUBLIC_URL` 应与浏览器访问的地址一致。
- **忘记初始密码**：`sudo cat /opt/onefrog/.install.env`（改过账号后初始密码失效）。
- **安装后添加模型**：「设置 → 模型渠道」添加 OpenAI 兼容接口和 API Key。
