# 本地预览

在自己电脑上固定放一份项目，以后无论是你自己改，还是让 AI 改完开了 PR，都用同一条命令跑起来看效果。前端改动会立即刷新页面，后端改动会自动重启。

## 第一次准备（只做一次）

1. 安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)，打开它并保持运行。
2. 安装 Node.js 22（macOS：`brew install node@22`）。
3. 把项目克隆到一个固定目录，以后一直用它，例如：

   ```bash
   git clone https://github.com/llc370219/onefrog.git ~/Projects/onefrog
   ```

不需要安装 Go，后端在 Docker 里编译。

## 日常使用

在项目目录里执行：

| 想做什么 | 命令 |
| --- | --- |
| 看 PR #12 的改动 | `./scripts/dev.sh 12` |
| 看 main 上的最新代码 | `./scripts/dev.sh main` |
| 用当前目录的代码启动 | `./scripts/dev.sh` |
| 清空演示数据 | `./scripts/dev.sh reset` |
| 后台残留的后端没停 | `./scripts/dev.sh stop` |

启动后会自动打开 http://localhost:5173 ，演示账号 `admin` / `admin`。按 `Ctrl+C` 结束，后端会一起停掉。

- 第一次启动要下载前端依赖和 Go 依赖，需要几分钟；之后几秒就能起来。依赖有变化时脚本会自动重新安装。
- 演示数据（账号、服务器、对话、设置）保存在项目里的 `.dev/data`，下次启动还在。它只在本机，不会提交到 Git。
- 服务只监听本机 127.0.0.1，局域网里的其他设备访问不到。
- 切换 PR 前，脚本会检查有没有未提交的改动；有的话会停下来提醒你，不会覆盖。

## 检查 AI 开的 PR

1. AI 推送分支并开 PR 后，记下 PR 编号。
2. 执行 `./scripts/dev.sh 编号`，在浏览器里实际点一遍。界面改动记得用右上角的按钮在浅色和深色之间各看一次，也可以把浏览器窗口拉窄看手机布局。
3. 没问题就在 GitHub 上合并 PR；有问题直接把看到的现象告诉 AI，它改完推送后，再执行一次同样的命令即可看到新版本。

## 常见问题

- **提示 Docker 没有在运行**：打开 Docker Desktop，等左下角显示运行中再试。
- **5173 或 8080 端口被占用**：关掉占用端口的程序。后端端口也可以换：`OF_DEV_API_PORT=18080 ./scripts/dev.sh`。
- **后端没启动成功**：脚本会打印后端最后的日志；也可以执行 `docker logs onefrog-dev-api` 查看。
