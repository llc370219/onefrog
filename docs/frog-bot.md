# AI 助理

OneFrog 的「AI 助理」采用 [Frog Bot](https://github.com/llc370219/frog-bot) 的架构：一个聊天层负责和你对话，要动手的事交给后台 Agent。后台任务在服务器上继续运行，刷新或关掉页面都不会中断；任务卡可以暂停、恢复、取消和重试，需要你确认时会弹出审批卡片。

## 每个 Bot 都是一个助理

「Bot」页里每个启用的 Bot（「自定义模块」Bot 除外）都是 AI 助理里的一个助理，各自有自己的对话、后台任务队列、记忆和工作区。主控排在第一位，默认打开它。

- 新建、改名、改职责、换模型和停用都在「Bot」页做，AI 助理页会跟着变。停用的 Bot 会从列表里消失，数据保留，重新启用后接着用。
- 「Bot」页每一行的「对话」按钮会打开这个 Bot 的对话。
- 宽屏时左侧是助理列表，窄屏时点顶部的名字切换。
- 助理之间可以互相询问（`ask_agent`）和留言（`message_agent`）。每个助理有自己的私有记忆，也有同一账号下所有助理共用的共享记忆。「Bot」页里记下的记忆会作为参考带进对话。

## 和 OneFrog 的关系

| 能力 | 使用的 OneFrog 部分 |
| --- | --- |
| 登录和账号 | OneFrog 登录。每个账号有自己的一套助理、对话和工作区，互相看不到 |
| 模型 | 每个 Bot 在「Bot」页或「设置 → 模型」里的模型路由：聊天用对话路由，后台 Agent 用协作路由，用量记在这个 Bot 名下 |
| 服务器操作 | OneFrog 原有的工具（`run_command`、`inspect_services`、`connect_server`、`install_probe`、`panel`、`manage_modules`、`manage_module_record`、`generate_secret`），按 Bot 的职责提供，和以前一样走 OneFrog 的审批、审计和指纹校验 |
| 密钥 | 「密钥保险箱」。助理的密钥卡片直接存进这里，没有单独的保险箱 |
| 定时 | 「模块 → 自动化」。在对话里让助理定时做事，会在自动化里新建一条，执行者就是这个 Bot |

## 服务器和审批

- 对话页右上角可以给每个助理选「可直接操作的服务器」。选中的服务器上，命令按「设置 → 审批」的模式处理：智能模式下普通命令直接执行，有风险的命令会弹出审批卡片；手动模式下每条都要确认；仅规划模式下不执行远程操作。
- 没选中的服务器，每条命令都会先请你确认，风险按高处理。
- 审批卡片和选项卡片是两种卡片。OneFrog 要求确认的操作只能「批准一次」，参数变了要重新确认；审批卡片 10 分钟内没处理会自动拒绝。
- 只有确认过 SSH 主机指纹的服务器才能执行命令。指纹没确认或对不上时，命令不会执行。
- 灾难性命令（例如删除根目录）无论什么审批模式都会被拦下。
- 助理的文件工具只能访问它自己的工作区，不能在面板所在的宿主机上执行 Shell。

## 密钥

- 用到密钥时写成 `{{secret:NAME}}`，真实值只在执行那一刻替换，模型看不到。输出和日志里出现的密钥值（包括 base64、URL 编码等形式）会被替换成 `[secret:NAME]`。
- 助理只能引用由大写字母、数字和下划线组成的密钥名（例如 `GITHUB_TOKEN`）。保险箱里其他名字的密钥它看不到。

## 自动化

- 自动化到点后，任务进入执行者 Bot 的后台队列，过程和审批卡片在这个助理的对话里，结果写回自动化卡片和变更记录。
- 自动化里指定的服务器，在这次运行中算作「选中的服务器」。自动化自己的审批模式（例如仅规划）照常生效；全局审批设为关闭时，无人值守的运行按智能审批处理。
- 定时计划的新建、暂停、恢复和删除都要在审批卡片上确认，聊天里说「同意」不算数。
- 执行者是「自定义模块」Bot 的自动化，以及没有账号归属的旧自动化，仍由原来的任务引擎执行。

## 升级

- v0.1.32/0.1.33 的单个 Frog Bot 成为主控的助理：原来的对话、任务、记忆和工作区都还在，不需要手动迁移。
- 执行者是「Frog Bot（AI 助理）」的旧自动化由主控执行，可以重新选执行者和服务器。
- 其他 Bot 第一次打开时是空对话。

## 数据

- 对话事件、任务检查点和记忆按账号加密保存在 `OF_DATA_DIR/frog-bot/`：主控在账号目录下，其他 Bot 在 `bots/` 下，工作区在 `workspace/` 和 `workspace-bots/` 下。面板的备份与迁移会一起打包。
- 密钥只保存在 OneFrog 的保险箱里，这个目录里没有密钥。

## 仍由原任务引擎处理的部分

- 面板首页的指令卡片、服务监控和订阅页的「让 Bot 检查」。
- 「模块 → 自定义模块」的构建器。

## 开发

- 前端通过 `/api/frog-bot/bots` 和 `/api/frog-bot/bots/{id}/*` 访问，走 OneFrog 的登录和跨站请求校验，事件流支持断线续传。`/api/frog-bot/bots/{id}/scope` 读写这个助理可直接操作的服务器。
- 代码基于 Frog Bot `0ca375c`（v0.1.2，MIT），位于 `internal/frogbot/` 和 `web/src/frogbot/`。宿主适配位于 `internal/api/frogbot.go`、`internal/api/frogbot_host.go`、`internal/bot/frogbot.go`（模型）和 `internal/bot/frogbridge.go`（OneFrog 工具与审批）。嵌入模式（`bot.Config.Host`）下，Frog Bot 自带的登录、模型设置、本地保险箱、定时器和 Bot 管理都不启用。
