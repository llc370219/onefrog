# 线路检测与公共节点使用

三网检测由服务器探针向所选省份的电信、联通、移动节点发起 TCP 80 端口连接；成功后立即关闭，不下载文件。它反映的是服务器到该节点的连通性，不能代表该省所有用户的实际访问体验。

## 默认策略

- 系统指标默认每 15 秒采集上报；线路检测独立调度，默认每 60 秒一次，可在测速设置中选择 120 或 300 秒。
- 每个目标每轮尝试 3 次，单次超时 2 秒；默认三个目标合计约 9 次连接尝试/分钟，实际受错峰和上报轮询影响可能更少。
- 启动随机错峰 0–15 秒，各目标独立增加 0–10% 的间隔抖动。完全失败或无法检测时按目标指数退避，默认从 120 秒开始，最多 900 秒；恢复成功后回到设定间隔。
- 后台最多同时执行 3 个目标检测。慢 DNS 或连接超时不会阻塞系统资源指标上报，也不会叠加同一目标的检测任务。
- 复用最近结果时保留原检测时间；历史色块按检测时间去重，避免把每次资源上报误当成一次新检测。

## 指标含义

TCP 显示「连接失败率」：失败连接次数 / 本轮尝试次数。它包含超时、拒绝连接等情况，不等同于 IP 数据包丢包率。每轮只有 3 次尝试，比例较粗，仅供观察趋势。自定义 ICMP 目标仍显示实际 Ping 返回的「丢包率」。

## 应用到已安装探针

更新面板后，在服务器卡片的测速设置选择省份和间隔，点击「保存并应用」。面板会通过已保存且绑定主机指纹的 SSH 凭据，升级该节点的 OneFrog 探针脚本并更新配置，保留原上报令牌、地址、资源采样间隔、网卡和其他检测目标。应用失败会尝试恢复原脚本和配置。

仅更新面板镜像不会自动替换其他服务器上已安装的脚本。手动部署的节点可重新下载采集脚本，并在配置中加入 `"ping_interval_seconds": 60`，重启探针后生效；不填写时新脚本也默认使用 60 秒。

## 公共节点与参考

- [Zstatic 节点目录及使用须知](https://www.zstaticcdn.com/)提供网络健康检测参考，并禁止扫描、压测、攻击及未经授权用途。公开目录不是无限量使用授权；规模较大时应提高间隔、联系节点维护者或使用自有且获授权的目标。
- [哪吒官方服务监控说明](https://nezha.wiki/guide/services.html)分别配置 TCPing/ICMP Ping 和检测间隔；协议与间隔独立于资源指标。
- [Komari 官方 API 示例](https://komari-monitor.github.io/komari-document/dev/api.html)包含独立 Ping 任务及 60 秒间隔示例；这不是公共节点方承诺的限额。
- [社区三网设置教程](https://www.shuidl.com/3830.html)使用所选省份的 Zstatic 省级节点和 TCP 80 端口。[另一篇社区实践](https://linux.do/t/topic/798067)也说明部分节点不响应 ICMP，使用 TCPing。

60 秒是本项目采用的保守默认值，不代表服务方保证不会限流，也不保证所有 VPS 商家的使用规则相同。
