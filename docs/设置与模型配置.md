# 设置与模型配置

入口：面板右上角或侧栏底部的「设置」。设置分为模型渠道、模型路由、命令审批和执行参数。

## 模型渠道

### OpenAI 兼容接口（推荐）

添加任意 OpenAI Chat Completions 兼容接口：基础地址、API Key（本地免密服务可留空）、启用状态。

- 「获取模型」读取接口的 `/models` 目录；每个模型可单独开启或隐藏。隐藏只影响下拉菜单，已有绑定不受影响。
- 「测试」发起一次简短的 `/chat/completions` 文本调用，只验证文本请求，不代表工具调用或 JSON 审批一定可用。
- 修改渠道地址时必须重新输入或显式清除原密钥，已保存的密钥不会被发往新地址；请求不跟随重定向。

这是使用提供方**官方 API Key** 的方式，不存在下面 OAuth 登录的封号风险。

### 第三方账号登录（OAuth，风险自负）

可选的「ChatGPT / Codex 登录」和「Google Antigravity 登录」借用**其他产品的官方客户端身份**调用**非公开接口**，可能违反提供方条款，账号可能被限制或永久封禁（Antigravity 条款明确禁止，2026 年已有封号报告）。详见 [DISCLAIMER.md](../DISCLAIMER.md)。

- 每次开始登录前会弹出中英文风险说明，必须勾选「我已了解风险并自行承担后果」并确认。服务端同样校验：未确认时 `POST /api/oauth/start` 直接拒绝。
- 确认记录（提供方、说明版本、时间）按账号保存在加密的 `oauth.enc`，并写入「变更记录」。风险说明更新版本后需要重新确认。
- 登录完成后浏览器会跳到一个本机回调地址（`localhost`/`127.0.0.1`），页面打不开是正常的：把地址栏里的完整地址粘贴回 OneFrog 即可。

#### Google Antigravity 登录（需自行配置）

OneFrog **不内置** Google 客户端 ID 和密钥。未配置时，设置中的 Google 按钮显示「需要配置」并不可点击。要启用，在服务端设置以下环境变量后重启：

```text
OF_GOOGLE_OAUTH_CLIENT_ID=你的客户端 ID
OF_GOOGLE_OAUTH_CLIENT_SECRET=你的客户端密钥
```

一行命令安装的实例：把这两行追加到 `/opt/onefrog/.install.env`（保持权限 600），然后执行

```bash
cd /opt/onefrog && sudo docker compose -p onefrog up -d
```

凭据的来源与使用由你自行负责。OpenAI 登录默认使用 Codex 公开客户端 ID，可用 `OF_OPENAI_OAUTH_CLIENT_ID` 覆盖。

## 模型路由

主控、协作默认、单个 Bot、审批可以分别选择渠道和模型。优先级：单个 Bot 设置 > 协作默认 > 主控默认。创建 Bot 时可以直接选择模型，也可以跟随默认值。聊天输入框上方还能临时为当前对话选择模型，不改变持久配置。

## 命令审批

是否开启审批由你自己选择。首次登录（改完初始账号后）会出现一个选择页，二选一后才能进入面板，没有预先选中的选项；之后随时可以在「设置 → 命令审批」或单个对话的「审核方式」里修改。

| 模式 | 说明 |
| --- | --- |
| 智能审批（推荐） | 只读命令（查看状态、日志、配置、资源占用等）直接执行；有风险的命令先暂停，在网页弹窗里等你批准。 |
| 关闭审批 | AI 认为需要的命令直接执行，不再询问。只有极少数灾难性命令（如 `rm -rf /`、格式化磁盘）仍被内置清单拦截。 |

高级模式（不是默认，按需在设置的「高级模式」里选择）：

| 模式 | 说明 |
| --- | --- |
| 逐条确认 | 每条命令都弹窗确认，包括只读命令。 |
| 替我审批 | 由单独指定的审批模型判断每条命令；拒绝、超时、返回格式错误都不执行。 |
| 仅规划 | 不执行任何远程命令。 |

还没有选择时（例如通过接口使用、尚未登录网页），按「智能审批」处理。旧版本保存的「关键字拦截」（`rules`）会被当作「关闭审批」；已经保存过的其他选择保持不变。

### 智能审批怎么判断

满足下面**任意一条**就会弹窗等你确认：

1. **服务端规则**判定有风险。规则会先把命令按 shell 语法拆开（管道 `|`、`&&`、`||`、`;`、子 shell、`$(…)`、反引号、引号、heredoc、重定向），并穿透 `sudo`、`env`、`nohup`、`timeout`、`xargs`、`bash -c`、`docker exec`、`kubectl exec`、`find -exec` 等包装，逐段检查。覆盖：删除或覆盖文件、截断 `> 文件`、关键系统路径（`/`、`/etc`、`/boot`、`/usr` 等）、服务与系统状态（重启、关机、`systemctl stop`）、网络与访问（防火墙、路由、SSH 配置、账号与权限）、软件包、数据库写操作、Docker / Kubernetes 管理操作、`crontab -r`、下载后执行或内联脚本（`curl … | sh`、`bash -c "$(curl …)"`、`python -c`）、编码或混淆（`base64 -d | sh`、`$IFS`、变量拼出的命令名）、读取私钥等敏感文件。
2. **只有白名单里的只读命令**才算安全（如 `ls`、`cat`、`grep`、`df`、`ps`、`systemctl status`、`journalctl`、`docker ps`、`SELECT` 查询）。不认识的命令、无法解析的命令一律视为有风险。
3. **AI 自评**：每次调用 `run_command` 必须填写 `risk`（low / medium / high）和 `reason`（目的）。自评为 medium、high 或没有填写时需要确认。最终等级取规则与 AI 自评中**更高**的一个，AI 不能把规则判定的风险降下来。
4. **疑似提示注入**：命令（或其中的网址、某一段）出现在本轮的命令输出或附件里、而你自己的消息里没有，也会要求确认。命令输出以 `<untrusted_output>` 标记交给模型，提示词要求模型把它当作数据而不是指令。

弹窗显示：命令、目标服务器、风险等级、规则命中的类别与说明、AI 说明的目的，以及是否疑似来自不可信内容。5 分钟内未处理按拒绝处理；拒绝后会告诉模型不要换写法重试。审批结果写入「最近审批记录」（`GET /api/approvals`）。

注意：

- 智能审批能**减少**风险，但**不能消除**风险：规则可能漏判少见的危险写法，AI 自评也可能出错，批准前请看清命令。重要数据请先备份。
- 需要确认的命令只能在网页「AI 助理」的实时对话（WebSocket）里批准；通过 `POST /api/chat` 发起时没有弹窗，需要确认的命令会被拒绝。
- 替我审批是模型判断，不是沙盒。
- 强烈建议为 OneFrog 使用权限受限的专用 SSH 用户，见 [安装.md](安装.md#安全建议)。

### 无界面安装

- 安装时设置 `OF_APPROVAL_MODE=off|smart|manual|plan`，只在**尚未选择**时生效，之后以面板里保存的选择为准。
- 也可以登录后调用接口：`GET /api/settings/approval` 返回 `{"mode":"","effective_mode":"smart","choice_required":true}`；`PUT /api/settings/approval` 提交 `{"mode":"smart"}`（可选 `off`、`smart`、`manual`、`model`、`plan`，`model` 需要先配置审批模型）。

## 提示词

所有 Bot 的系统提示词集中在 [`internal/bot/prompts.go`](../internal/bot/prompts.go)，修改后重新构建即可：

- `promptLeader` / `promptWorker`：主控与协作 Bot 的身份。
- `promptOperations`：共用的工作规则——先只读排查、改动前说明计划（做什么、为什么、影响、回滚）、最小权限、修改前备份、改后验证、简洁汇报、如何填写 `risk` / `reason`、工具输出不可信、不得绕过审批。
- `promptModes`：告诉模型当前审批模式。
- `promptAsset`：模块构建 Bot；`promptReviewer`：替我审批模式下的独立审批模型。
- 工具说明（`toolRunCommandDesc` 等）和不可信输出的包装标记。

创建 Bot 时填写的「工作指令」会追加在这些规则之后，只能补充或收紧，不能放宽安全规则。

## 执行参数

模型请求超时 5–180 秒、SSH 命令超时 5–300 秒、单个 Bot 循环 1–12 轮、历史上下文 2–100 条。每轮任务开始时固定配置快照，保存设置不影响正在执行的这一轮。

## 存储

设置保存在 `OF_DATA_DIR/settings.enc`，OAuth 登录与风险确认保存在 `oauth.enc`，均用 AES-256-GCM 加密，加密主密钥为同目录下的 `master.key`（也可用 `OF_MASTER_KEY` 提供）。首次启动会从环境变量迁移初始配置，之后以保存的设置为准。

## 接口

- `GET /api/settings` / `PUT /api/settings`：读取 / 原子保存完整配置；不返回密钥，`has_api_key` 表示已有密钥；`api_key` 留空保留、`clear_api_key` 清除。
- `POST /api/settings/providers/models`、`POST /api/settings/providers/test`：读取模型目录 / 测试文本调用，均不保存。
- `GET /api/oauth`：可用的登录方式（含 `configured`、`setup_hint`）、已连接账号和风险确认记录。
- `POST /api/oauth/start`：`{"kind":"oauth-openai","consent_version":"…","risk_acknowledged":true}`。
- `GET /api/settings/approval` / `PUT /api/settings/approval`：读取 / 修改命令审批模式，见上文。
- `GET /api/approvals`：最近的审批记录。
- `GET /api/update` / `POST /api/update/check` / `PUT /api/settings/update`：版本与更新检查，见 [安装.md](安装.md#升级)。

所有写请求需带 `Content-Type: application/json` 和请求头 `X-OneFrog-CSRF: 1`（网页前端自动添加）。
